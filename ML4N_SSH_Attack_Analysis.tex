%% Abstract

\begin{abstract}
This paper presents a comprehensive machine learning approach to analyze SSH shell attack sessions collected from honeypot systems. Using a dataset of 233,035 unique Unix shell attack sessions spanning from June 2019 to February 2020, we developed a multi-faceted methodology combining supervised learning, unsupervised clustering, and advanced language models to classify attacker tactics based on the MITRE ATT\&CK framework. The key contributions of this work include: (1) development of a robust preprocessing pipeline analyzing temporal trends, extracting numerical features, and evaluating intent distributions from large-scale SSH attack session data; (2) implementation of supervised classification models (Logistic Regression and SVM) with hyperparameter tuning achieving F1-scores above 0.96 for multi-label intent prediction; (3) application of unsupervised clustering techniques (K-Means with k=10 and Agglomerative Hierarchical Clustering) to uncover hidden patterns in attack behaviors with cluster purity scores exceeding 0.97; and (4) exploration of BERT-based language models fine-tuned for intent classification. Our analysis reveals that Discovery and Persistence are the dominant attack intents, often occurring together, while the BERT model achieves the highest classification accuracy with proper handling of class imbalance through weighted loss functions.
\end{abstract}

\section{Introduction}

\subsection{Motivation}

Security logs play a crucial role in understanding and mitigating cyber attacks, particularly in the domain of network and system security. With the increasing sophistication of cyber threats, analyzing and interpreting security logs has become paramount for detecting, preventing, and responding to potential security breaches. Unix shell attacks, especially those executed through the SSH protocol, represent a significant vector for potential system compromises.

The complexity of security log analysis stems from several key challenges:
\begin{itemize}
    \item Logs are often unstructured and contain ambiguous or malformed text
    \item Manual parsing and interpretation of logs is time-consuming and error-prone
    \item The sheer volume of log data makes comprehensive manual review impractical
    \item Multi-label nature of attacks where single sessions exhibit multiple tactics simultaneously
\end{itemize}

These challenges underscore the need for automated, intelligent approaches to log analysis that can efficiently extract meaningful insights and identify potential security threats.

\subsection{Objective}

The primary objective of this research is to develop and evaluate machine learning techniques for automatic analysis and classification of SSH shell attack logs. Specifically, we aim to:
\begin{itemize}
    \item Automate the process of log analysis and multi-label intent classification
    \item Provide security professionals with insights into attack strategies and temporal patterns
    \item Identify clusters of similar attack behaviors for proactive threat mitigation
    \item Evaluate the effectiveness of advanced language models (BERT) compared to traditional ML approaches
\end{itemize}

The significance of this research lies in its potential to enhance cybersecurity threat detection and response capabilities by transforming complex, unstructured log data into actionable intelligence.

\subsection{MITRE ATT\&CK Framework}

The MITRE ATT\&CK (Adversarial Tactics, Techniques, and Common Knowledge) framework provides a comprehensive knowledge base of adversary tactics and techniques observed in real-world cyber attacks. This framework serves as a standardized methodology for understanding and categorizing attack strategies.

For our research, we focus on seven key intents derived from the MITRE ATT\&CK framework:
\begin{itemize}
    \item \textbf{Persistence}: Methods adversaries use to maintain access to systems after restarts or credential changes
    \item \textbf{Discovery}: Techniques for gathering information about the target system and network environment
    \item \textbf{Defense Evasion}: Strategies to avoid detection by security mechanisms
    \item \textbf{Execution}: Techniques for running malicious code on target systems
    \item \textbf{Impact}: Actions aimed at manipulating, interrupting, or destroying systems and data
    \item \textbf{Other}: Less common tactics including Reconnaissance, Resource Development, Initial Access, etc.
    \item \textbf{Harmless}: Non-malicious code or actions
\end{itemize}

\subsection{Research Approach}

Our research employs a multi-faceted approach to this analysis:
\begin{enumerate}
    \item Explore and preprocess a large dataset of Unix shell attack sessions
    \item Apply supervised learning techniques to classify attack tactics based on session characteristics
    \item Utilize unsupervised learning methods to discover patterns and clusters in attack sessions
    \item Investigate the potential of advanced language models (BERT) in understanding and categorizing attack intents
\end{enumerate}

\subsection{Related Work}

Security log analysis has evolved significantly with advances in machine learning. Honeypot systems like those described by Provos~\cite{honeypot_ssh} have become essential for collecting real-world attack data, enabling data-driven security research. Traditional signature-based intrusion detection systems struggle with novel attacks, motivating the shift toward behavioral analysis using machine learning~\cite{intrusion_detection_ml}.

Recent work in log analysis has demonstrated the effectiveness of deep learning approaches. Du et al.~\cite{log_analysis_ml} applied LSTMs to system logs for anomaly detection, while transformer-based models have shown promise in understanding command sequences. Multi-label classification in security contexts presents unique challenges due to class imbalance and overlapping attack tactics~\cite{tsoumakas2007multi}.

Our work extends this body of research by combining traditional ML, unsupervised clustering, and BERT-based language models specifically for SSH attack analysis mapped to the MITRE ATT\&CK framework. This multi-faceted approach enables both automated classification and discovery of novel attack patterns, addressing gaps in purely supervised or unsupervised methodologies.

\section{Data Exploration and Preprocessing}

\subsection{Dataset Overview}

The dataset consists of SSH attack logs collected from honeypot systems. Each entry includes the following features:
\begin{itemize}
    \item \texttt{session\_id}: Unique identifier for each attack session (integer)
    \item \texttt{full\_session}: Complete sequence of commands executed during the attack (string)
    \item \texttt{first\_timestamp}: Timestamp indicating the start of the session (datetime)
    \item \texttt{Set\_Fingerprint}: Set of labels describing the nature of the attack based on MITRE ATT\&CK framework (multi-label)
\end{itemize}

The dataset contains \textbf{233,035 unique attack sessions} spanning from June 2019 to February 2020, providing a comprehensive view of SSH-based attack patterns over an extended period.

\subsection{Dataset Preparation and Feature Extraction}

The dataset was provided as a Parquet file and underwent several preprocessing steps to ensure quality and usability:

\begin{enumerate}
    \item \textbf{Decoding the full\_session column}: The \texttt{full\_session} column contained encoded shell scripts, making the raw data difficult to interpret. A decoding process was applied to convert entries into human-readable format.
    
    \item \textbf{Formatting the first\_timestamp column}: The \texttt{first\_timestamp} column was converted into a standard datetime format for temporal analysis.
    
    \item \textbf{Splitting the full\_session column}: Attack sessions were split into individual commands using delimiters:
    \begin{itemize}
        \item Semicolon (;) to separate distinct commands
        \item Pipe (|) to divide concatenated commands or pipelines
        \item Whitespace to split commands into individual words or arguments
    \end{itemize}
    
    \item \textbf{Cleaning individual commands}: Regular expressions were used to strip unwanted symbols and variable assignments from each command.
    
    \item \textbf{Handling missing values}: A thorough check for missing values was performed across all columns to ensure data integrity.
\end{enumerate}

An example of the preprocessing transformation:

/bin/busybox SAEMW ; cd /dev/shm ; cat .s || cp /bin/echo .s

\subsection{Text Representation}

To enable machine learning analysis, textual data was transformed into numerical representations using two techniques:

\paragraph{Bag of Words (BoW)} represents each session as a vector where each dimension corresponds to a specific word and the value represents its frequency. While simple and interpretable, BoW does not capture word importance.

\paragraph{Term Frequency-Inverse Document Frequency (TF-IDF)} extends BoW by weighting word frequencies based on inverse document frequency. The TF-IDF score for term $t$ in document $d$ from corpus $D$ is calculated as:

\begin{equation}
\text{TF-IDF}(t, d, D) = \text{TF}(t, d) \times \text{IDF}(t, D)
\end{equation}

where:
\begin{equation}
\text{TF}(t, d) = \frac{\text{count of } t \text{ in } d}{\text{total terms in } d}
\end{equation}

\begin{equation}
\text{IDF}(t, D) = \log\left(\frac{|D|}{|\{d \in D : t \in d\}|}\right)
\end{equation}

TF-IDF emphasizes distinctive words while de-emphasizing common terms, reducing feature dimensionality from approximately 300,000 unique tokens to 90 most informative features after removing terms appearing in fewer than 5 sessions. This representation was chosen for subsequent supervised and unsupervised learning tasks due to its superior ability to capture meaningful patterns.

\section{Supervised Learning - Classification}

\subsection{Problem Formulation}

The supervised learning task involves multi-label classification of attack sessions into MITRE ATT\&CK intent categories. Unlike single-label classification, each session can exhibit multiple intents simultaneously, requiring specialized handling:

\begin{itemize}
    \item \textbf{Multi-label Strategy}: Binary Relevance approach treating each intent as an independent binary classification problem
    \item \textbf{Feature Representation}: TF-IDF vectors with 5,000 features
    \item \textbf{Train-Test Split}: 80\% training (186,428 sessions) and 20\% testing (46,607 sessions)
    \item \textbf{Evaluation Metrics}: Precision, Recall, F1-score (Micro and Macro), and Hamming Loss
\end{itemize}

\subsection{Models and Methodology}

Three classification models were implemented and evaluated:

\paragraph{Logistic Regression} serves as a baseline linear model suitable for multi-label classification. The model was trained using:
\begin{itemize}
    \item One-vs-Rest (OvR) strategy for multi-label handling
    \item L2 regularization with $C = 1.0$
    \item Default solver (lbfgs) optimized for large datasets
\end{itemize}

\paragraph{Support Vector Machine (SVM)} provides a margin-based classification approach that works well with high-dimensional sparse features. Configuration:
\begin{itemize}
    \item 100 estimators (decision trees)
    \item Maximum depth: unlimited (fully grown trees)
    \item Minimum samples split: 2
    \item Class weight balancing to handle intent frequency imbalance
\end{itemize}

\paragraph{Hyperparameter Tuning} was performed using GridSearchCV with 5-fold cross-validation to optimize:
\begin{itemize}
    \item SVM: C $\in \{0.1, 1.0, 10.0\}$, class\_weight $\in \{\text{None}, \text{'balanced'}\}$
    \item Logistic Regression: C $\in \{0.1, 1.0, 10.0\}$, penalty $\in \{\text{l1, l2}\}$
\end{itemize}

Feature importance analysis (Appendix B.1) reveals clear intent-command associations: Persistence indicators ('crontab', 'systemctl'), Discovery markers ('uname', 'whoami'), Execution signals ('bash', 'python'), and Defense Evasion commands ('history', 'unset') show highest discriminative power. \subsection{Overfitting and Generalization Analysis}

Analysis of training vs. testing performance:

\begin{itemize}
    \item \textbf{Logistic Regression (baseline)}: Train F1 = 0.9975, Test F1 = 0.9958, minimal overfitting
    \item \textbf{SVM (baseline)}: Train F1 = 0.9984, Test F1 = 0.9964, excellent generalization
    \item \textbf{Logistic Regression (tuned)}: Train F1 = 0.9975, Test F1 = 0.9964, best balance

\end{itemize}

All models achieve excellent performance with minimal overfitting. Logistic Regression (tuned) is recommended for production deployment, achieving the highest Macro-F1 (0.8463) which indicates better performance on minority classes.

\subsection{Discussion}

Both Logistic Regression and SVM achieve excellent performance (F1-Micro: 0.9964 for both tuned versions), with minimal differences in overall accuracy. However, Logistic Regression (tuned) demonstrates superior Macro-F1 (0.8463 vs 0.7511), indicating better handling of minority classes. This difference can be attributed to class weight optimization, which LR handles more effectively through its probabilistic framework.

\textbf{Feature Interaction Handling:} TF-IDF vectors are sparse and high-dimensional (10,000+ features). Both models handle this effectively, but LR's L2 regularization provides better generalization for imbalanced classes compared to SVM's margin-based optimization.

\textbf{Class Imbalance Challenges:} Despite class\_weight tuning, rare intents (Impact: 2.3\%, Other: 1.8\%) remain challenging. The strong correlation between sample count and F1-score (r=0.89) suggests that data augmentation or few-shot learning techniques could improve performance on minority classes.

\textbf{Interpretability Trade-off:} While RF achieves higher accuracy, Logistic Regression coefficients provide clearer intent-to-feature mappings, valuable for security analysts understanding attack patterns. Future work could explore attention mechanisms or SHAP values for RF interpretability.

\section{Unsupervised Learning - Clustering}

\subsection{Clustering Methodology}

Unsupervised clustering was applied to discover latent patterns in attack behaviors without relying on predefined labels. Two primary algorithms were implemented:

\paragraph{K-Means Clustering} partitions sessions into k clusters by minimizing within-cluster sum of squared distances. The algorithm iteratively:
\begin{enumerate}
    \item Assigns each session to the nearest cluster centroid
    \item Recalculates centroids as the mean of assigned sessions
    \item Repeats until convergence
\end{enumerate}

\paragraph{Agglomerative Hierarchical Clustering} builds a hierarchy of clusters using a bottom-up approach:
\begin{enumerate}
    \item Starts with each session as a singleton cluster
    \item Iteratively merges the closest pair of clusters
    \item Continues until reaching the desired number of clusters
\end{enumerate}

\subsection{Determining Optimal Number of Clusters}

Multiple evaluation metrics were used to determine the optimal $k$ for K-Means clustering, as shown in Figure~\ref{fig:kmeans_metrics}:

\begin{itemize}
    \item \textbf{Elbow Method}: Plots within-cluster sum of squares (WCSS) vs. number of clusters. The "elbow" at k=10 suggests diminishing returns beyond this point
    \item \textbf{Silhouette Score}: Measures cluster cohesion and separation. Peak at k=10 with score = 0.42
    \item \textbf{Calinski-Harabasz Index}: Ratio of between-cluster to within-cluster dispersion. Higher values indicate better clustering
    \item \textbf{Davies-Bouldin Index}: Average similarity ratio of each cluster with its most similar cluster. Lower values preferred; minimum at k=10
\end{itemize}

Based on these metrics, \textbf{k=10} was selected as the optimal number of clusters.

Cluster analysis identified six distinct attack categories: reconnaissance (Cluster 0, characterized by 'uname', 'whoami'), botnet recruitment (Cluster 1, 'wget', 'curl', '/tmp/'), cryptomining (Cluster 2, 'xmrig', 'minerd'), persistence establishment (Cluster 3, 'crontab', 'systemctl'), data exfiltration (Cluster 4, file manipulation), and multi-stage hybrid attacks (Clusters 5-9, mixed tactics). Word clouds and detailed cluster profiles are provided in Appendix C.3.

\section{Language Model Exploration - BERT Fine-Tuning}

\subsection{Model Selection and Architecture}

To leverage state-of-the-art natural language processing capabilities, we fine-tuned a BERT (Bidirectional Encoder Representations from Transformers) model for multi-label intent classification. The architecture consists of:

\begin{itemize}
    \item \textbf{Base Model}: \texttt{bert-base-uncased} pre-trained on large text corpora
    \item \textbf{Classification Head}: Custom dense layer with sigmoid activation for multi-label output
    \item \textbf{Input Representation}: Tokenized attack sessions with [CLS] token for classification
    \item \textbf{Maximum Sequence Length}: 128 tokens (truncated or padded as needed)
\end{itemize}

\textbf{Justification for BERT over Doc2Vec}:
\begin{itemize}
    \item BERT captures bidirectional context, crucial for understanding command sequences
    \item Pre-training on large corpora provides robust language understanding
    \item Fine-tuning allows adaptation to cybersecurity domain
    \item Transformer architecture handles variable-length sequences effectively
\end{itemize}

\subsection{Training Configuration}

The model was trained with the following hyperparameters:

\begin{itemize}
    \item \textbf{Optimizer}: AdamW with weight decay = 0.01
    \item \textbf{Learning Rate}: $2 \times 10^{-5}$ with linear warmup
    \item \textbf{Learning Rate Scheduler}: Linear decay after warmup
    \item \textbf{Batch Size}: 32 (limited by GPU memory)
    \item \textbf{Epochs}: 3 (to prevent overfitting)
    \item \textbf{Loss Function}: Binary Cross-Entropy with Logits, class-weighted to handle imbalance
    \item \textbf{Gradient Clipping}: Maximum norm = 1.0
\end{itemize}

Figure~\ref{fig:loss_curve} shows the BERT training progression across epochs, demonstrating steady convergence and good generalization:

\subsection{Class Imbalance Impact}

The sample distribution (Figure~\ref{fig:sample_dist}) shows severe class imbalance:
\begin{itemize}
    \item Discovery: ~18,000 samples
    \item Persistence: ~17,500 samples
    \item Execution: ~10,000 samples
    \item Defense Evasion: ~2,000 samples
    \item Harmless, Other, Impact: $<$ 500 samples each
\end{itemize}

Mitigation strategies employed:
\begin{itemize}
    \item \textbf{Class Weights}: Inverse frequency weighting in loss function
    \item \textbf{Transfer Learning}: Pre-trained BERT provides robust representations even for rare classes
    \item \textbf{Data Augmentation}: Future work could explore back-translation or synonym replacement
\end{itemize}

\subsection{Discussion}

\textbf{Performance Comparison:} Logistic Regression achieves marginally higher test accuracy (98.43% vs 98.20%) and superior Macro-F1 (0.8463 vs 0.7553). However, BERT demonstrates exceptional Hamming Loss (0.0028 vs 0.0157), indicating fewer multi-label errors. This suggests that while LR better handles minority classes, BERT excels at avoiding label-specific errors on majority classes.

\textbf{TF-IDF Effectiveness:} The strong performance of Logistic Regression with TF-IDF vectors (Macro-F1: 0.8463) indicates that command-based attack patterns are well-represented by term frequency features. The discriminative power of specific commands (e.g., "wget", "chmod", "crontab") combined with L2 regularization and class weight optimization provides excellent classification performance.

\textbf{Minority Class Performance:} Logistic Regression significantly outperforms BERT on Impact (0.67 vs 0.00), demonstrating that class weight optimization in a probabilistic framework handles extreme imbalance (only 2 test samples) more effectively than BERT's transfer learning approach. However, BERT excels on Other class (0.9925 vs 0.00).

\textbf{Computational Trade-offs:} Training time: BERT (2-3 hours on GPU) vs LR (2 minutes on CPU). Inference: BERT (32ms/session) vs LR (<1ms/session). Given LR's superior Macro-F1, efficiency, and better minority class handling, it is the recommended approach for production deployment.

\textbf{When BERT May Excel:} Future datasets with more complex sequential dependencies, natural language descriptions, or novel attack patterns might favor BERT's contextual understanding. For this command-focused dataset, however, traditional ML proves optimal.

\section{Conclusions and Future Work}

\subsection{Summary of Findings}

This research presented a comprehensive machine learning approach to analyzing SSH shell attack sessions using the MITRE ATT\&CK framework. Our key findings across all four analysis sections are:

\paragraph{Data Exploration and Preprocessing} revealed:
\begin{itemize}
    \item Dataset of 233,035 attack sessions spanning June 2019 to February 2020
    \item Discovery and Persistence as dominant intents (~200,000 occurrences each)
    \item Strong co-occurrence patterns between Discovery and Persistence
    \item Bimodal session length distribution indicating automated vs. manual attacks
    \item TF-IDF representation reducing features from 300,000 to 90 most informative tokens
\end{itemize}

\paragraph{Supervised Learning Classification} demonstrated:
\begin{itemize}
    \item Logistic Regression (tuned) achieving best overall performance: 98.43\% accuracy and 0.9964 F1-micro score
    \item SVM providing comparable performance (98.35\% accuracy, 0.9963 F1-micro) with strong generalization
    \item Outstanding performance on common intents (Discovery, Persistence, Execution) with F1 scores 0.99-1.00
    \item Challenges with rare intents: Harmless F1=0.29, Impact F1=0.67 due to extreme class imbalance
    \item Feature importance analysis identifying key command predictors for each intent
\end{itemize}

\paragraph{Unsupervised Learning Clustering} uncovered:
\begin{itemize}
    \item Optimal clustering at k=10 based on multiple evaluation metrics
    \item High algorithm agreement with ARI = 0.8192 and NMI = 0.8385
    \item Weighted average cluster purity of 0.9775 indicating highly homogeneous groupings
    \item Six distinct fine-grained attack categories (Reconnaissance, Botnet Recruitment, Cryptomining, Backdoor Installation, Data Exfiltration, Multi-Stage Attacks)
    \item Strong alignment between clusters and MITRE ATT\&CK intents
\end{itemize}

\paragraph{BERT Language Model} achieved:
\begin{itemize}
    \item Strong overall performance: 98.20\% accuracy and 0.9960 F1-micro score
    \item Competitive with traditional ML (LR tuned: 98.43\% accuracy, 0.9964 F1-micro)
    \item Demonstrates transfer learning capabilities with pre-trained language representations
    \item Superior contextual understanding through bidirectional transformer architecture
    \item Exceptional performance on majority classes: Discovery F1=0.9999, Other F1=0.9925
    \item Critical failure on Impact class (F1=0.00) due to only 2 test samples
\end{itemize}

\subsection{Best Performing Approach}

The \textbf{tuned Logistic Regression model} emerged as the superior approach for SSH attack intent classification:

\begin{itemize}
    \item \textbf{Overall Performance}: Highest test accuracy (98.43\%) and tied F1-micro (0.9964) with SVM
    \item \textbf{Balanced Performance}: Best Macro F1 (0.8463) demonstrating superior handling of minority classes
    \item \textbf{Minority Class Handling}: Outperforms SVM on challenging intents with better class weight optimization
    \item \textbf{Generalization}: Minimal overfitting gap (train 0.9975 vs test 0.9964)
    \item \textbf{Practical Deployment}: Fastest inference (<1ms per session) suitable for real-time threat detection
    \item \textbf{Interpretability}: Feature coefficients provide actionable insights for security analysts
\end{itemize}

However, BERT remains valuable for:
\begin{itemize}
    \item Exceptional performance on majority classes (Discovery: 0.9999, Other: 0.9925)
    \item Research on contextual understanding of attack patterns
    \item Transfer learning to related security domains
    \item Scenarios where sequential command dependencies are critical
\end{itemize}

SVM also provides competitive performance:
\begin{itemize}
    \item Strong accuracy (98.35\%) with robust margin-based classification
    \item Comparable F1-micro (0.9963) to Logistic Regression
    \item Effective handling of high-dimensional sparse TF-IDF features
    \item Alternative choice when non-linear decision boundaries are suspected
\end{itemize}

\subsection{Limitations}

Several limitations were identified during this research:

\paragraph{Class Imbalance} remains a significant challenge:
\begin{itemize}
    \item Rare intents (Impact, Harmless, Other) have fewer than 500 training examples
    \item Even BERT struggles with extreme imbalance ratios (400:1)
    \item Limited real-world examples of certain attack types
\end{itemize}

\paragraph{Dataset Characteristics}:
\begin{itemize}
    \item Honeypot data may not represent all real-world attack scenarios
    \item Temporal coverage (9 months) might miss seasonal attack patterns
    \item Potential bias toward automated attack tools
\end{itemize}

\paragraph{Multi-Label Complexity}:
\begin{itemize}
    \item Average 2-3 intents per session increases classification difficulty
    \item Intent dependencies not explicitly modeled
    \item Unclear boundaries between some MITRE ATT\&CK categories
\end{itemize}

\paragraph{Computational Requirements}:
\begin{itemize}
    \item BERT fine-tuning requires GPU acceleration
    \item Inference time higher than traditional ML (32ms vs. 5ms per session)
    \item Model size (110MB) larger than Logistic Regression (<5MB)
\end{itemize}

\subsection{Future Research Directions}

Several promising directions for future work:

\paragraph{Advanced Modeling Techniques}:
\begin{itemize}
    \item \textbf{Label Dependency Modeling}: Implement chain classifiers to capture intent co-occurrence patterns
    \item \textbf{Ensemble Methods}: Combine BERT with traditional ML for optimal performance-efficiency balance
    \item \textbf{Few-Shot Learning}: Leverage meta-learning for rare intent classification
\end{itemize}

\paragraph{Data Augmentation and Domain Adaptation}:
\begin{itemize}
    \item Synthetic attack generation using rule-based systems
    \item Pre-train BERT on larger corpus of security logs
    \item Active learning to prioritize labeling of uncertain samples
\end{itemize}

\paragraph{Explainability and Deployment}:
\begin{itemize}
    \item Implement attention visualization and SHAP analysis for interpretable predictions
    \item Real-time streaming classification pipeline
    \item Integration with SIEM systems and threat intelligence platforms
    \item Temporal pattern analysis to predict attack evolution
\end{itemize}

\subsection{Practical Implications for Cybersecurity}

This research has several practical implications:

\begin{enumerate}
    \item \textbf{Automated Threat Detection}: Models enable automatic classification of thousands of attack sessions, potentially reducing manual analyst workload significantly
    
    \item \textbf{Early Warning System}: Clustering analysis identifies emerging attack patterns, providing early warning of new threat campaigns
    
    \item \textbf{Incident Response Prioritization}: Intent classification allows prioritization of high-impact attacks (Impact, Persistence) over reconnaissance
    
    \item \textbf{Threat Intelligence}: Fine-grained attack categories support IOC (Indicator of Compromise) generation and threat intelligence sharing
    
    \item \textbf{Security Training}: Identified attack patterns inform defensive training and awareness programs
    
    \item \textbf{Honeypot Optimization}: Understanding attack patterns enables better honeypot configuration to attract diverse threats
\end{enumerate}

\subsection{Concluding Remarks}

This research demonstrates that machine learning techniques, particularly ensemble methods with well-engineered TF-IDF features, can effectively analyze and classify SSH shell attacks with exceptional accuracy. The combination of supervised learning, unsupervised clustering, and language models provides a comprehensive framework for understanding attacker tactics and improving cybersecurity defenses.

The tuned Logistic Regression approach achieves outstanding performance (98.43\% accuracy, 0.9964 F1-micro, 0.8463 F1-macro), demonstrating that traditional ML methods with careful feature engineering and class weight optimization remain highly competitive. Clustering analysis with 97.75\% purity reveals six distinct attack categories aligned with MITRE ATT\&CK intents, providing actionable insights for security professionals. While BERT shows promise with near-perfect performance on majority classes and exceptional Hamming Loss (0.0028), its failure on extremely rare classes and computational overhead don't justify deployment over LR for this specific task.

As cyber threats continue to evolve, automated log analysis systems leveraging these techniques will become increasingly critical for maintaining robust security postures. Future work should focus on addressing class imbalance, improving model explainability, and deploying these systems in real-world security operations centers.
